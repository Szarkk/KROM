# Krom Features Overview

This document outlines all the planned features for Krom, a deep cleaning tool inspired by TronScript. Features are organized into core stages (mirroring Tron's structure) with enhancements and add-ons integrated where they fit logically. Each feature includes a description and implementation ideas for reference.

Krom is designed to be modular, with optional toggles via command-line flags or a config file (e.g., YAML). Prioritize safety: always include backups, verbose logging, and undo options where possible.

## Core Stages

| Stage | Description | Implementation Ideas | Prerequisites |
|-------|-------------|----------------------|---------------|
| **Prep** | Create backups (e.g., system restore point or registry export), kill suspicious processes, and prep for safe mode if needed. Optional: Allow skipping backups via --no-backup flag for advanced users (not recommended; enabled by default for safety). | Use Python's `subprocess` to run tools like `rkill` equivalents or built-in Windows commands. Backup via `shutil` for files/registry. | None (entry point). |
| **Temp Clean** | Wipe temp files, browser caches, event logs, and update caches. | Leverage libraries like `tempfile` or custom scripts; integrate CCleaner-like logic with `os.walk` for directories. | Hard: Prep (unlocks files via process kills, backups for safety); Recommended: None. |
| **De-Bloat** | Remove pre-installed bloatware, unwanted apps, and services (e.g., disable telemetry). | Parse installed apps via WMI (Windows Management Instrumentation) in Python, or use PowerShell integration. Custom lists for common offenders like Candy Crush. | Hard: Prep, Temp Clean (clears caches bloatware uses, backups for registry tweaks); Recommended: None. |
| **Disinfect** | Scan and remove malware/adware using open-source tools. | Integrate with ClamAV or similar via API/subprocess; add simple heuristic scans for known bad files. | Hard: Prep, De-Bloat (removes bloat hiding malware, backups for AV installs); Recommended: Temp Clean (clears temp malware drops). |
| **Repair** | Fix system files, permissions, and network issues. | Run `sfc /scannow`, `chkdsk`, or DISM equivalents; use `winreg` for registry tweaks. | Hard: Prep, Disinfect (fixes malware damage, backups for DISM/sfc changes); Recommended: De-Bloat (removes conflicting apps). |
| **Patch** | Update system and common apps (e.g., 7-Zip). Supports offline mode to skip online checks and use bundled patches. | Check for updates via APIs or bundled offline patches; avoid full Windows Update to keep it lightweight. In offline mode (--offline flag), prioritize local patch dirs and log skips for network calls. | Hard: Prep, Repair (patches stable system, backups before updates); Recommended: Disinfect (removes malware exploiting vulnerabilities). |
| **Optimize** | Defrag drives (skip SSDs), reset pagefile, and trim resources. | Use `defrag` commands or Python's `psutil` for monitoring/optimization. | Hard: Prep, Patch (optimizes post-updates, backups for pagefile tweaks); Recommended: Repair (ensures disk health first). |
| **Wrap-Up** | Generate logs, send reports (e.g., email), and clean up tools. | Use `logging` module for detailed outputs; optional SMTP for emails. | Hard: All prior stages (compiles logs/reports); Recommended: None. |
| **Custom** | Allow users to add their own scripts or plugins. | A directory for user .py or .bat files that Krom executes at the end. | Hard: All prior (executes post-clean); Recommended: Wrap-Up (for logging plugin output). |

## Enhancements and Add-Ons

These build on the core stages or add new capabilities. They can be enabled/disabled to keep runs customizable.

| Enhancement | Associated Stage | Description | Implementation Ideas | Prerequisites |
|-------------|------------------|-------------|----------------------|---------------|
| **Cloud Backup Integration** | Prep | Optional: Back up key files (e.g., docs) to Dropbox/Google Drive before deep cleans. | Use APIs from `dropbox` or `google-api-python-client` libs—require user auth tokens. Keep it opt-in for privacy. | Hard: Prep (ties to core backups); Recommended: None. |
| **Browser Cleanup** | Temp Clean | Target browser-specific junk: extensions, history, cookies, and site data. Support major ones like Chrome, Firefox, Edge. | Use browser APIs or direct file access (e.g., delete `Extensions` folder contents after backup). Add a "safe extensions" whitelist. | Hard: Temp Clean (wipes browser caches first); Recommended: Prep (kills interfering browser processes). |
| **Privacy Scrub** | After De-Bloat | Deep-dive into privacy: clear tracking data, disable ad trackers, and nuke telemetry beyond basics. E.g., block Windows tracking hosts, clear DNS cache, and remove browser fingerprints. | Use hosts file edits (append to `C:\Windows\System32\drivers\etc\hosts`), run `ipconfig /flushdns`, and integrate with tools like `bleachbit` via subprocess. For browsers, target specific dirs like Chrome's `User Data`. Bonus: Generate a privacy report on what was blocked. | Hard: De-Bloat (scrubs after bloat removal); Recommended: Temp Clean (clears DNS first). |
| **Uninstall Residue Remover** | After De-Bloat | Hunt for leftovers from uninstalled apps (registry keys, folders). | Scan common paths like `Program Files` remnants and registry hives; use pattern matching. | Hard: De-Bloat (hunts after main removal); Recommended: Prep (backups registry scans). |
| **Driver Audit** | After Repair | Check for outdated drivers and suggest updates (but don't auto-install to avoid bluescreens). Focus on critical ones like graphics/network. | Use `pnputil` or parse Device Manager output. Integrate with a safe source like offline driver packs or API checks if online mode is enabled. | Hard: Repair (audits post-fixes); Recommended: None. |
| **Startup Manager** | During Optimize | Audit and disable unnecessary startup items to speed boot times. Include services, tasks, and registry entries. | Query via `wmic startup` or Python's `winreg` and `psutil.boot_time()`. Let users review/interact via a simple CLI menu before changes. | Hard: Optimize (manages post-optimization); Recommended: De-Bloat (disables bloat startups). |
| **Benchmark & Report** | Wrap-Up | Run before/after performance tests (e.g., disk speed, CPU usage) and visualize results in the log. | Use `psutil` for metrics, `speedtest-cli` for network if applicable, and generate charts with `matplotlib` (save as PNG in logs). This screams "portfolio polish." | Hard: Wrap-Up (generates pre/post metrics); Recommended: All stages (for full before/after). |
| **Scheduled Mode** | Post-Run Option | Set up recurring runs via Windows Task Scheduler or cron (for cross-platform). | Use `schtasks` commands in script or Python's `schedule` lib. Prompt user at end: "Schedule weekly?" | Hard: Wrap-Up (sets up post-run); Recommended: None. |
| **Hardware Health Check** | New Stage: Diagnostics (After Repair or Standalone) | Scan for hardware issues like disk health (SMART), overheating, or battery status on laptops. | Pull SMART via `wmic diskdrive` or `smartctl` if bundled. Alert on failures. | Hard: Repair (diagnostics post-fixes); Recommended: Optimize (disk health ties to defrag). |
| **Secure Wipe** | Optional Add-On (Pre-Run or Standalone) | Offer secure deletion for user-specified files/folders using multi-pass overwrites (e.g., DoD standard). Useful for sensitive data before cleanup. | Implement with `shred`-like logic in Python (random overwrites via `os` and `secrets` module). Integrate as a pre-run option. | Hard: Prep (backups before wipes); Recommended: Temp Clean (clears temp first). |
| **Startup Intro** | Global (On Launch) | Display ASCII art, welcome message, and suggest `--help` when running without flags. | Simple print statements in `main.py`; detect via `sys.argv` length. Optional flag `--no-intro` to disable. Add colors with `termcolor` if desired. | None (global). |

## Additional Notes
- **Tech Stack Recommendations:** Python for cross-platform compatibility (bundle into exe with PyInstaller). Use libraries like `psutil`, `winreg`, `subprocess`, and `logging` for core functionality.
- **Safety and Usability:** All changes should be reversible where possible. Include a GUI option (e.g., Tkinter) for non-tech users. Test extensively in VMs.
- **Workflow Dependencies:** Stages run sequentially by default for safety/effectiveness (e.g., Prep unlocks files for Temp Clean). Standalone mode (--standalone) skips this but logs warnings; implement checks in main.py dispatcher.
- **Portfolio Focus:** Document design choices in code comments and GitHub README. Add visualizations and custom plugins to showcase extensibility.
